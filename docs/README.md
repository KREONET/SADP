# SADP 문서 홈

SADP 문서는 역할별 가이드와 작업별 runbook으로 나뉩니다. 문서의 명령보다 현재 checkout의
`bash ./sadp --list`와 각 명령 `--help`가 우선입니다. 서로 다르면 소스에 맞춰 문서도 함께
고칩니다.

| 앱 개발자 | [개발자 가이드](developer-guide.md) | 소스/Dockerfile, 정책, Secret 분류, API | cluster admin |

## 핵심 개념

### Portal은 신청 창구입니다

단일 앱은 최종 제출 때 서버가 검증하고 신청을 만듭니다. AppGroup은 **앱 구성 확인**과
**배포 신청**이 분리돼 있습니다. 신청 뒤 실제 반영은 build, Forgejo PR, Argo CD를 거칩니다.

### Git이 선언 상태의 기록입니다

Portal과 플랫폼 변경은 GitOps PR로 반영합니다. cluster를 직접 고치면 Argo self-heal이 되돌릴 수
있습니다. 긴급 변경도 site.env/계약/Git에 수렴시켜야 합니다.

### Secret 값은 Git에 넣지 않습니다

Git에는 Secret 이름, OpenBao path, key 이름만 둡니다. 값은 OpenBao → ESO → Kubernetes Secret으로
전달합니다. bootstrap Secret은 Git 밖의 root-only 파일을 사용합니다.

### 사이트 설정은 외부 env에서 시작합니다

```text
/etc/sadp/site.env
  → configure-site.py --write
  → contracts/platform-production.yaml
  → platform/ · argocd/ · apps/ · rke/
  → diff 검토와 commit/push
  → Argo CD
```

`# Generated by` 파일을 직접 수정하지 않습니다. 운영 env가 없는 생성기 개발 checkout만 계약을
직접 고치고 renderer와 tests를 함께 변경합니다.

## 표기와 안전 규칙

- `<PORTAL_HOST>`, `<NAMESPACE>`는 실제 환경값으로 바꿉니다.
- `example.invalid`와 문서용 IP 대역은 실제 적용에 사용할 수 없습니다.
- `Private`는 값 자체가 아니라 공개 문서에 기록하지 말라는 표기입니다.
- 통합 installer의 no-apply는 검증과 실행할 명령 출력만 하며 host/cluster를 바꾸지 않습니다.
- node apply는 RKE2를 자동 재시작하지 않습니다.
- 실제 password, token, private key, kubeconfig, 내부 FQDN/IP를 공용 문서에 기록하지 않습니다.
