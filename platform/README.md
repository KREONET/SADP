# SADP 플랫폼 구현 안내

> 대상: 생성된 플랫폼 리소스를 진단하는 관리자와 유지보수 개발자
> 신규 설치 절차: [docs/installation.md](../docs/installation.md)

이 디렉터리는 설치 순서를 손으로 실행하는 runbook이 아닙니다. 대부분 계약에서 렌더된 리소스와
Argo CD가 적용하는 플랫폼 values입니다. 정상 설치는 `bash ./sadp --install`을 사용합니다.

## 1. 소유권과 생성 흐름

```text
/etc/sadp/site.env (Git 밖, 사이트별 비밀 아닌 입력)
  → configure-site.py --write
  → contracts/platform-production.yaml
  → render-network/exposure/rancher/quota
  → platform/**, argocd/**, apps/**, rke/**
  → Argo CD Application
  → 클러스터
```

머리에 `Generated by` 또는 자동 생성 설명이 있는 파일은 직접 수정하지 않습니다. 상류
`site.env`와 생성 로직을 수정하고 다시 렌더링합니다. 실제 `site.env`가 없는 개발용 checkout만
계약을 직접 수정할 수 있으며, 이 경우에도 renderer와 전체 테스트를 함께 실행해야 합니다.

## 2. 디렉터리별 역할

| 경로 | 역할 | 주요 소유자 |
| --- | --- | --- |
| `network/` | host firewall/proxy/NMS, CoreDNS, cert-manager egress 입력 | `render-network.py` |
| `dns/` | RKE2 CoreDNS split DNS | `render-network.py` |
| `exposure/` | Gateway, Route, 외부 서비스, 내부 CA | `render-exposure.py`와 정적 리소스 |
| `cert-manager/` | ClusterIssuer/Certificate | `render-exposure.py` |
| `rancher/` | Project와 group RBAC | `render-rancher.py` |
| `keycloak/` | in-cluster 또는 external Service/EndpointSlice | `configure-site.py` |
| `openbao/` | OpenBao TLS/PVC/audit 기반 리소스 | Argo + bootstrap script |
| `external-secrets/` | ESO values | Argo CD |
| `reloader/` | Reloader values | Argo CD |
| `monitoring/` | Prometheus/Loki/Alloy values와 동기화 이미지 목록 | Argo CD |
| `portal/` | Portal의 AppGroup Namespace 조회 권한 | Argo CD |
| `quota/` | Namespace ResourceQuota/LimitRange | `render-quota.py` |

Secret은 이 디렉터리에 넣지 않습니다. OpenBao → ESO → ExternalSecret 경로를 사용합니다.
DNS-01 TSIG처럼 OpenBao보다 먼저 필요한 bootstrap 자격증명도 Git에는 두지 않고 통합 설치기가
root-only 파일에서 Kubernetes Secret으로 적용합니다.

## 3. Gateway와 노출

MetalLB는 계약 `spec.gateway.addressPoolRange`를 광고하고 Envoy Gateway Service는
`spec.gateway.vip`를 사용합니다. 외부 진입점은 Envoy 하나이며 RKE2의 bundled ingress-nginx는
비활성 상태여야 합니다.

`spec.public.mode`:

| 모드 | 실제 공개 경로 |
| --- | --- |
| `nat` | 경계 장비의 public IP 80/443을 Gateway VIP 80/443으로 DNAT |
| `direct` | public IP가 노드 external NIC에 있고 Envoy Service `externalIPs`로 사용 |

public DNS에는 apex와 wildcard A record가 모두 필요합니다. 실제 host와 IP는 계약에서 읽고,
문서 예제 값을 그대로 사용하지 않습니다.

확인:

```bash
kubectl get gatewayclass
kubectl get gateway -n <GATEWAY_NAMESPACE>
kubectl get service -n <GATEWAY_NAMESPACE> -o wide
kubectl get httproute -A
```

## 4. TLS 진행 상태

ACME 설치는 한 번에 HTTPS까지 강제로 진행하지 않습니다.

1. `issuerMode=staging`, staging 검증 미완료, Gateway TLS 미완료
2. staging Certificate Ready 후 `ACME_STAGING_VERIFIED=true`, `TLS_ISSUER_MODE=production`
3. production Certificate Ready 후 `EXISTING_GATEWAY_TLS_READY=true`

각 단계에서 site.env 갱신 → render → diff 검토 → commit/push → cluster phase를 반복합니다.
3단계 전에는 통합 설치기가 플랫폼 기반만 설치하고 서비스 bootstrap과 앱 배포를 보류합니다.
자세한 절차는 [Let's Encrypt DNS-01](../docs/letsencrypt-dns01.md)을 따릅니다.

## 5. Argo CD 소유 리소스

`argocd/bootstrap-application.yaml` 아래 Application들이 플랫폼을 소유합니다. 현재 주요 항목은
MetalLB, Envoy Gateway, cert-manager, Rancher, OpenBao, ESO, Reloader, Prometheus, Loki, Alloy,
platform-resources와 기본 앱입니다.

controller/chart를 로컬 `helm install`로 겹쳐 설치하지 않습니다. Argo로 만든 리소스에는 Helm
release metadata가 없기 때문에 직접 Helm release로 가져오면 소유권 충돌이 납니다.

```bash
kubectl get applications -n devtroncd
kubectl get applications -n devtroncd \
  -o custom-columns=NAME:.metadata.name,SYNC:.status.sync.status,HEALTH:.status.health.status
```

## 6. 플랫폼 설치 스크립트가 하는 일

`scripts/cluster/install-testbed-platform.sh`는 controller를 직접 Helm 설치하지 않습니다.

- 3노드 Ready와 TLS 입력/Secret 검증
- CoreDNS split DNS 적용
- cert-manager controller 전용 proxy 적용 확인
- 제공 인증서 또는 cert-manager Secret 경계 처리
- Keycloak in-cluster 리소스 또는 external Endpoint 적용
- ESO/Reloader/OpenBao Argo Application과 rollout 대기
- Gateway/플랫폼 Route 적용
- monitoring 이미지 동기화와 Prometheus/Loki/Alloy Argo rollout 대기

따라서 이 스크립트 전에 Argo repository, AppProject, app-of-apps bootstrap이 완료돼야 합니다.

## 7. Rancher

Rancher는 관리 대상 클러스터 안에서 `local` 클러스터를 관리합니다. chart는 Ingress를 만들지 않고
Envoy Gateway가 TLS를 종료합니다. Project/RBAC의 실제 이름과 group은 계약이 기준입니다.
자세한 내용은 [Rancher 구현 안내](rancher/README.md)를 사용합니다.

## 8. 버전 기준

구성 요소 버전의 단일 기준은 [versions.lock.yaml](../versions.lock.yaml)입니다. 문서에 적힌 숫자와
다르면 lock file과 Argo Application targetRevision을 먼저 확인합니다. 임의로 chart의 최신 버전을
사용하지 않습니다.

## 9. 변경과 검증

사이트 입력을 바꿀 때:

```bash
python3 scripts/site/configure-site.py \
  --env-file /etc/sadp/site.env --check
python3 scripts/site/configure-site.py \
  --env-file /etc/sadp/site.env --write
bash ./sadp --test
```

`site.env` 없이 계약 생성 로직을 개발하는 경우:

```bash
bash ./sadp --render-all
bash ./sadp --test
```

cluster 적용 전에는 생성 diff에 실제 Secret/IP/FQDN이 새로 노출되지 않았는지 확인합니다. 사이트
전용 private 값은 Git 문서나 공용 template에 넣지 않습니다.
